# 治理规范

借鉴 Agent 原生工程实践：**系统拥有事实，Agent 拥有推理，人类拥有最终决策**。本规范是硬性约束，不是建议。

## 1. 工具安全四级分类

| 级别 | 定义 | 执行策略 | 本仓库例子 |
|---|---|---|---|
| L1 只读 | 不改变任何状态 | Agent 自治 | 库存查询、订单查询、比价、报表 |
| L2 可逆写 | 平台可回滚/有版本号 | 自治 + 审计日志 + 异常回滚 | 出入库、面单、采购单、工单流转 |
| L3 不可逆写 | 资金动作、无法撤销 | 强制人工审批，执行前预演 | 退款执行、快递拦截、审单发货 |
| L4 客户外发 | 发给真实用户，不可撤回 | 起草→批准→发送，草稿与发送分离 | 平台 IM 回复、评价回复、营销触达 |

## 2. HITL 外发状态机（L4 必用）

```
drafted → approved → sending → sent
                          ↘ failed → compensated
```

- Agent 只能产生 `drafted`，不得直接发送；
- 每个外发动作带 `idempotencyKey`，防崩溃重发；
- 发送失败进入 `compensated`（补偿或人工跟进），不得静默重试超过 3 次。

## 3. 能力台账四态

`planned 规划中 → registered 已调研 → integrated 已接入 → verified 已验收`

**注册 ≠ 可用**：进入 `verified` 必须记录验证环境、日期与证据。第三方能力矩阵中标称的工具数不等于可调用数，以实测为准。

## 4. 幂等与恢复

- 所有写操作带 `idempotencyKey`（建议：`业务域:业务ID:动作:日期`）；
- 定时任务以「日期 + 任务名」为幂等键，同键不重复执行；
- 输出先写临时区，再原子提交，失败可断点续跑。

## 5. 预算与循环防护

- 每个 Skill 声明 `maxToolCalls` 与 `maxTokens`，超限即停并告警；
- 计费型连接器设月度额度上限，达 80% 预警；
- 工具重试 ≤3 次；连续 5 次调用未产生新信息即终止，防递归死循环。

## 6. 验收门禁（每个 P0 Skill 必须定义）

| Skill | 确定性门禁 | 业务验收 |
|---|---|---|
| 多平台对账 | 注入 10 个已知差异样本（少收款/多扣佣/漏单）全部识别 | 人工抽查 1 天账单，差异清单零漏报 |
| 经营日报 | 随机抽 1 平台，Agent 数字 vs 后台人工数字误差 = 0 | 连续 5 天自动推送无人工修正 |
| 客服应答 | 30 条历史问题回归集，引用必须带来源 | 无证据时必须答「需人工确认」，不得臆造 |
| 库存预警 | 构造 3 个断货场景全部命中 | 误报率 <5% |

失败样本整理为 Golden Corpus，每次改动回归。

## 7. 授权与合规边界

- `.env.example` 只允许占位符；CI 扫描禁止真实凭证入库（`scripts/check-secrets.mjs`）；
- 平台开放 API 的签名逻辑只保留接口位，接入前需自行取得开放平台资质；
- 不收录逆向协议、绕过风控、批量爬取私有数据的实现；
- 公开内容不得包含真实店铺名、客户信息、内网域名。
