# 架构说明

## 分层

```
┌──────────────────────────────────────────────────────────┐
│  Agent / 编排层（skills/ 中的 Skill 说明书 + 你的 Agent）    │
└───────────────┬──────────────────────────────────────────┘
                │ MCP（stdio / streamable http）
┌───────────────▼──────────────────────────────────────────┐
│  能力层：mcp/ 自建 Server（8）  +  adapters/ 第三方（25）   │
│  统一契约：Zod 入参校验 · 幂等键 · dry-run · L1–L4 分级     │
└───────────────┬──────────────────────────────────────────┘
                │ 只读优先，写操作经审批
┌───────────────▼──────────────────────────────────────────┐
│  事实源层：WMS / OMS / ERP / 平台开放 API / 支付通道         │
│  规则：每个数据域只有一个事实权威，禁止交叉缓存              │
└──────────────────────────────────────────────────────────┘
```

## 事实源登记（同一事实源原则）

| 数据域 | 事实权威 | 写入方 | 缓存策略 |
|---|---|---|---|
| 库存 | WMS | 仅 WMS | 实时读，不缓存 |
| 订单 | OMS（平台回传为唯一来源） | 仅平台回传通道 | 会话内 ≤5 分钟 |
| 价格 | 商品中台 | 审批后的 Agent（L2） | 实时读 |
| 资金 | 平台账单 + 支付通道 | 只读，双源核对 | 快照留档 |
| 客户会话 | 客服系统 | 仅客服模块 | 不缓存 |

## 四条协作链路

1. **智能补货链**：销量预测 → 采购建议 → 采购入库 → 商品库存同步 → 营销放量。
2. **大促作战链**：活动上线 → 订单峰值审单 → 优先级发货 → 客服 FAQ 预置 → 对账与利润回哺。
3. **售后闭环链**：投诉接入 → 并行查订单/轨迹/会话 → 定责 → 退款或拦截 → 财务记录 → 计入售后率。
4. **数据回哺链**：全模块事件汇入分析层 → 日报/预警/归因 → 分发给采购、营销、商品、客服。

## 单 Server 内部结构

```
mcp/<name>/
├─ src/index.ts    Server 装配、stdio 传输、工具注册
├─ src/tools.ts    工具定义（名称、描述、Zod 入参、安全级别、幂等要求）
├─ src/client.ts   真实 API 客户端 + mock 实现（DRY_RUN 切换）
└─ test/*.test.mjs dry-run 冒烟测试
```

写操作统一约定：

- 入参必须包含 `idempotencyKey`（除纯查询）；
- 返回结构统一 `{ ok, data, mock?, warnings? }`；
- `DRY_RUN=1` 或缺少凭证时返回 `mock: true` 的预演结果，绝不落真实副作用。
