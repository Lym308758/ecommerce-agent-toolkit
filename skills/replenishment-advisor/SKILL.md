# 智能补货建议

> 业务环节：**采购供应** ｜ 安全分级：**L1** ｜ 台账状态：`planned` ｜ 优先级：P0

## 何时使用

当某 SKU 可用库存低于安全水位、或运营询问「该补多少」时使用。

## 输入契约

- `sales_window`：近 N 天销量（建议 14/28 天）
- `onhand` / `in_transit`：可用与在途库存
- `lead_time_days`：供应商交期
- `safety_stock`：安全库存（可选，缺省按销量波动计算）

## 工作流

1. 拉取销量窗口数据，剔除促销异常日（超过均值 3 倍的日期标注为异常）。
2. 计算日均销量与波动系数，按交期折算在途覆盖天数。
3. 计算建议补货量：`max(0, 日均 × (交期 + 安全天数) - 可用 - 在途)`。
4. 按「缺货天数」分级：紧急（<3 天）/ 关注（3–7 天）/ 充裕（>7 天）。
5. 输出补货清单，标注每个 SKU 的**依据来源**与**数据缺口**。

## 输出契约

```json
{ "items": [{ "sku": "", "suggestQty": 0, "urgency": "high|mid|low", "basis": "日均12.4×(7+3)-40-30=54", "dataGap": null }], "warnings": ["SKU-A 销量窗口存在 2 天异常值已剔除"] }
```

## 验收门禁

- 与人工补货单逐 SKU 对比，偏差 <10% 视为通过。
- 数据缺失时必须输出 `dataGap`，禁止用估算值填空。
- 新品（无历史销量）不得给出补货量，只输出「需人工定价与首单量」。

## 失败样本（Golden Corpus）

- 断货期（销量被截断为 0）→ 必须用断货前窗口估算，并在 warnings 标注。
- 大促后窗口 → 促销期数据默认剔除，改用平时段。
- 多仓场景 → 按仓分别计算，不得合并后再算。

## 依赖能力

- `mcp/wms-mcp get_stock`
- `mcp/erp-scm-mcp list_purchase_orders`

## 边界

- 本 Skill 只产出**结论与建议**；L2 及以上写动作必须经人工确认后由对应 MCP 执行。
- 所有事实性输出必须可回溯到数据源；无来源时输出「需人工确认」，不得臆造。
- 定时类用法必须带 `runKey`（日期 + 任务名）保证幂等。
